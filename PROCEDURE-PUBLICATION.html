Procédure de publication du wiki

Ce document est destiné aux agents qui modifient le wiki.

Architecture

  • Sources à modifier : /Users/ludwigtrossel/Documents/agreg-oraux
  • Générateur : scripts/build-wiki-site.py
  • Rendu local, entièrement régénéré : site/
  • Dépôt public : /Users/ludwigtrossel/Documents/agreg-oraux-site
  • Dépôt GitHub : https://github.com/Monsieur-Zinj/agreg-oraux-site
  • Site : https://monsieur-zinj.github.io/agreg-oraux-site/
  • Service automatique macOS : com.ludwigtrossel.agreg-oraux-autopublish

Le dossier source agreg-oraux n’est pas un dépôt Git. Le dépôt Git est agreg-oraux-site, mais il ne doit pas être édité directement : son contenu est remplacé par synchronisation depuis agreg-oraux/site.

Procédure normale

  1. Modifier uniquement les sources dans /Users/ludwigtrossel/Documents/agreg-oraux : fichiers Markdown, notebooks, site-assets/ ou générateur.

  2. Ne jamais modifier directement site/ ni /Users/ludwigtrossel/Documents/agreg-oraux-site.

  3. Depuis la racine des sources, exécuter les contrôles :

    cd /Users/ludwigtrossel/Documents/agreg-oraux
python3 -m pytest -q
python3 scripts/build-wiki-site.py

  4. Vérifier le résultat local pertinent dans site/. Pour une source chemin/page.md, la sortie est en général site/chemin/page.html. Un README.md devient l’index.html de son dossier.

  5. Laisser le LaunchAgent publier automatiquement. Il surveille les fichiers .md, .ipynb, scripts/build-wiki-site.py et site-assets/; après stabilisation, il reconstruit, synchronise le rendu vers le dépôt public, crée un commit et pousse main.

  6. Vérifier la publication dans le dépôt public, puis sur GitHub :

    cd /Users/ludwigtrossel/Documents/agreg-oraux-site
git status --short
git log -1 --oneline
git rev-list --count '@{upstream}..HEAD'

    Résultat attendu : état propre et 0 commit en attente de push. Vérifier aussi que la page HTML concernée existe dans ce dépôt. Enfin, ouvrir son URL sous https://monsieur-zinj.github.io/agreg-oraux-site/ ; GitHub Pages peut avoir un court délai après le push.

Une tâche n’est pas considérée comme publiée sur la seule foi d’un build local : il faut constater le fichier dans le dépôt public et le push correspondant. Pour une modification importante, contrôler également la page servie.

Publication immédiate ou rattrapage

Si le service automatique n’est pas actif, contrôler son état :

launchctl print gui/$(id -u)/com.ludwigtrossel.agreg-oraux-autopublish

Pour lancer une publication complète une seule fois :

cd /Users/ludwigtrossel/Documents/agreg-oraux
python3 scripts/auto-publish.py --once

Ne pas lancer --once en parallèle d’une publication déjà en cours. Le script reconstruit le site, exécute rsync --delete, committe les changements du dépôt public et pousse origin main.

Journaux :

  • /Users/ludwigtrossel/Library/Logs/agreg-oraux-autopublish.log
  • /Users/ludwigtrossel/Library/Logs/agreg-oraux-autopublish-error.log

En cas d’échec, lire d’abord les dernières entrées des deux journaux, corriger la cause, relancer les tests et le build, puis laisser le service réessayer. Il retente automatiquement les push en attente toutes les 60 secondes.

Règles de sûreté

  • Tout Markdown et tout notebook sous les sources, hors dossiers exclus par le générateur, peut devenir public. Ne jamais y écrire de secret, donnée personnelle ou note privée.
  • Ne pas placer manuellement de contenu dans site/ : le prochain build le supprimera.
  • Ne pas faire de commit manuel dans le dépôt public pour du contenu éditorial : la prochaine synchronisation peut l’écraser.
  • Ne pas annoncer une publication réussie sans lecture de l’état exact du dépôt public.
  • Si les tests ou le build échouent, ne pas forcer la publication et signaler précisément le blocage.
